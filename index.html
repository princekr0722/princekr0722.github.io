DPatcher — autonomous AI engineer

Designed and built an AI engineer with deep, grounded knowledge of DrinkPrime's entire system. It answers from live sources rather than guessing, cross-referencing a pgvector knowledge base (Confluence + learned resolutions), a code-graph of the actual repositories, read-only production databases (MySQL/Mongo), and GKE runtime logs.

  • Made it a general-purpose engineering teammate the whole org can use — to understand how a feature works and why, debug and root-cause live issues across code + data + logs, draft test cases and edge cases, triage and resolve on-call incidents, and answer "where/how is X handled" onboarding questions — through both Slack and a web dashboard, with confidentiality controls that keep internal/technical detail off customer-facing threads.
  • Built it to get smarter over time, folding confirmed resolutions back into the knowledge base so recurring problems become self-answering — reducing repeat escalations and the team's dependency on a few subject-matter experts.
  • Owned the full product and its deployment: a role-based admin dashboard (Kong auth-gateway JWT, read/write access tiers), private staff DM assistant, live-tunable runtime settings, and a Dockerized rollout wired to external Postgres, MySQL/Mongo, and a code-graph service.

DPengram — code-knowledge platform

Designed and built a self-contained platform that transforms Git repositories into a queryable code graph (symbols, LSP-resolved call/usage graph, and semantic embeddings) and exposes it through a single MCP endpoint and REST API. Serves as the code-graph backbone behind DPatcher.

  • Built a transparent MCP proxy that forwards all upstream engine tools unchanged while extending them with first-party capabilities including repository discovery and ripgrep-powered filename/regex search. Any MCP client (e.g. Claude Code or Cursor) connects without modification and automatically inherits future engine capabilities.
  • Engineered reliable repository synchronization and deployment: serialized/coalesced indexing, incremental re-indexing from remote branch changes, stable project identities that self-heal after repository relocation, Docker-based organization deployment, and a zero-dependency single-file desktop executable with automatic engine provisioning, self-updates, and a React-based management UI.
What it changes day to day
  • Faster development — instantly locates the right code, its callers and its usages across every repo.
  • Quicker RCA — trace a bug's call path and blast radius in seconds instead of grepping around.
  • Fewer hallucinations — answers are grounded in real indexed code, semantic and full-text, not guesses.
  • Cross-repo questions — ask something spanning multiple services and get one coherent answer.
